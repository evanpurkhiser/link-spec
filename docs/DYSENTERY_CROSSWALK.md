The two primary pages are intentionally broader than menus alone.
`track_metadata.adoc` contains the field codec and the artwork, waveform, cue,
tag, playlist, alternate-sort, and all-track request families that this project
splits into separate oracle chapters. The supporting pages establish client
identity, location, slot, status, and connection context. Separate-protocol
pages remain visible so similarly named timing, metadata, or device messages
cannot be silently imported into Link Export conclusions.

## Adopted model

- Menu request -> `4000` count -> `3000` render -> `4001`/`4101`/`4201`.
- Packed requester/menu-location/source-slot/track-type context.
- Main, overlay, metadata-preview, and graphics menu locations.
- Uppercase UTF-16BE search with a trailing NUL.
- Root categories and sort behavior can depend on library/device settings.

## Where current evidence extends it

- The September 28 capture supplies RX3-era 12-argument row behavior and the
  concrete 20-row rekordbox root menu.
- Composite track item types encode the selected secondary column; the baseline
  Key row is `0x0f04`.
- The captured tree adds concrete Remixer, Label, BPM tolerance, recursive
  playlist, and modern Search examples.
- Rekordbox 7.2.19 symbols and SQL strings tie category/sort visibility and order
  to `djmdCategory` and `djmdSort`.
- A hash-pinned XDJ-RR client inventory extends the four commonly named
  Dysentery locations with direct functional evidence at every literal value
  `1..8`: loaded/playing views at 4, sort and one-track information at 5,
  Prepare/Tag List at 6, and category reload/information-jump/drag-drop paths
  at 7. The client also defines Delivery `2602` at fixed location 9; its
  Rekordbox matrix is declared and queued, so location 9 remains source evidence
  rather than an observed server result.
- Dysentery notes that the upper two bytes of a menu item's type may carry
  unexplained information on some players. The generated
  `data/static-analysis/item-type-domain.json` audit scans all 281 row-bearing
  canonical 7.2.19 golden files: 51,148 represented `0x4101` rows contain 85
  distinct argument-6 values, and none use the upper 16 bits. The maximum is
  `0x00002e04`. This is a Rekordbox 7.2.19 corpus boundary, not evidence that
  other software or player generations leave those bits clear.
- Dysentery's `0x2202` non-Rekordbox metadata request is a player-hosted role,
  not a contradiction of Rekordbox 7.2.19 returning `0x4003`. The generated
  `data/static-analysis/player-hosted-song-info.json` audit joins that public
  contract to player firmware: `0x2202` and `0x2302` have XDJ-RX player-side
  builders. Five XDJ generations issue `0x2402` expecting `0x4802` and register
  track length through one-way `0x2502`, but all five stub both server arms.
  Four newer firmwares preserve the names and formats without enough retained
  control-flow evidence to classify their serving behavior.

## Caveats

Dysentery documents several generations of players and rekordbox behavior. A
request described there is protocol precedent, not automatic proof of RX3 or
7.2.19 behavior. Conversely, RX-series devices may not broadcast every media
slot unsolicited. This research labels Dysentery-only claims **[DYS]** until a
capture, database row, executable path, or live isolated experiment confirms
them.

Three named-command conflicts are resolved explicitly:

- Dysentery's current `menus.adoc` and the live/static Rekordbox evidence agree
  that `0x1011` is Bitrate Root. The older inline `dbserver.clj` folder-menu
  comment is stale.
- Dysentery labels `0x2006` Folder Menu, while the recovered CDJ-3000 enum calls
  it `CMD_CACHE_FOLDER`. Rekordbox 7.2.19 routes all low-byte-`06` analysis-class
  requests to an unsupported arm, so neither name implies a working server
  command in this build.
- Dysentery tentatively labels `0x3e03` USB information, while the newer enum
  calls it `CMD_GET_IS_RBM_MOUNT`. Rekordbox routes it into `OnOtherCmd`, whose
  exact table ends at `0x3d03`, and rejects it.

`LINK_EXPORT_REQUEST_VOCABULARY.md` gives the full versioned crosswalk and
machine-readable provenance for every known command kind.

`ADJACENT_PAYLOAD_SERVICES.md` applies the same boundary to Dysentery's artwork
and analysis examples. Dysentery supplies proven player request shapes and
payload interpretations; the pinned Rekordbox binary independently establishes
the 7.2.19 AppSync/Master database split, JPEG gates, beat-count ceiling,
loader selection, and `EXT`/`2EX` atom behavior.
