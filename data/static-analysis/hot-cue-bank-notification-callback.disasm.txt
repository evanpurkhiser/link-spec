`PSvDBServerCallback` subobject at `UiProDJLink + 0x18` to the database server:

```text

0x1017b30ae  lea  rdx, [r13 + 0x18]
```

`PSvDBServer::Initialize(unsigned char, PSvDBServerCallback *, juce::String


`PSvDBMain::SetCallback` is a single pointer store:

`PSvDBMain::DeliverHCBankUpdate(int)` checks delivery-flag bit 1, loads the

```text
0x10252102b  mov  rax, qword ptr [rdi]
```

The installed concrete slot is the `UiProDJLink + 0x18` adjustment thunk for
`djplay::UiProDJLink::ReceiveUpdateEvent(PSvDBServerCallback::UpdateType,
int, int)` at `0x1017b4ee0`. Its class jump table begins at `0x1017b4f70` for
the thunk and has the same destinations as the unadjusted body shown below.

For class 3, the unadjusted body's jump table at `0x1017b4ec0` selects
`0x1017b4e74`, sets internal database-update type `0x1e`, clears the third
argument, preserves the CueID in the second argument, and tail-calls the
application database singleton:

The complete seven-entry class table resolves to:

```text
class 0 -> common path, internal type 0x1f, preserves both integer arguments
class 1 -> internal type 0x22, clears extra
class 2 -> internal type 0x1d, clears id and extra
class 3 -> internal type 0x1e, preserves id and clears extra
class 4 -> internal type 0x1c, clears extra
class 5 -> internal type 0x20, clears extra
class 6 -> internal type 0x21, clears extra
```

## Conclusion

The Hot Cue Bank setter's delivery sink is an in-process application callback.
For class 3 it becomes `DatabaseIF::notifyDBUpdated(0x1e, CueID, 0)`. No Link
Export socket send, packet serializer, or peer-recipient selection occurs in
this callback chain. Any UI or application work triggered later by
`notifyDBUpdated` is downstream of the server protocol and is not a setter
notification packet.
